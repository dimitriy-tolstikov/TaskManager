# План фичи «Цели» (Goals)

Статус: v1.0 — согласовано, готово к разработке

## 1. Суть

Цель: «за определённый промежуток времени выполнить N задач из направления/проекта X, M задач из Y, ...».
Пример: ежедневно с 6:00 до 9:00 — 1 задачу из «Работы», 1 из «Поиска работы», 1 из «Учёбы».

Если окно цели истекло, а квота не выполнена — цель становится **просроченной** и показывается на дашбордах и всех страницах так же заметно, как просроченная задача.

## 2. Предметная модель

- **Goal** — id, userId, name («Утро 6–9»), окно времени `startTime`/`endTime` (например 06:00–09:00), расписание (дни недели / ежедневно), active, createdAt.
- **GoalTarget** — id, goalId, scope: направление ИЛИ проект (areaId xor projectId), requiredCount (сколько задач).
- **GoalInstance** — конкретное вхождение цели: goalId, windowStart, windowEnd (конкретные дата-время). Хранится в БД, чтобы просроченные цели не «растворялись» в прошлом и чтобы можно было пометить «принято/отмахнулся».

**Подсчёт прогресса:** задача засчитывается в цель, если `completedAt ∈ [windowStart, windowEnd]` и задача принадлежит направлению/проекту таргета. Прогресс вычисляется на чтении (не денормализуем).

**Зачёт «в рамках дня»:** если задача завершена после окна, но в тот же календарный день — она закрывает **самое раннее невыполненное окно этого дня** с подходящим scope. Просроченные цели сегодняшнего дня ещё можно «отыграть»; цели прошлых дней закрываются только через ack.

**Статусы instance:** active (окно идёт) → done (все таргеты выполнены вовремя или отыграны в тот же день) / overdue (день прошёл, квота не выполнена). Overdue остаётся видимым, пока пользователь не «закроет» его (acknowledged) — иначе список просроченного растёт бесконечно.

## 3. Генерация instance'ов

- Instance создаётся **лениво при чтении** (сервис `goalService.getDashboard(userId)` материализует сегодняшние окна активных целей и окна за последние N=7 дней, если их ещё нет). Без worker'а и cron — проще и надёжно; когда появится worker в M4 (пуши), можно перенести материализацию туда.
- Окно «с 6 до 9» для сегодня строится из startTime/endTime + даты; если endTime < startTime — окно через полночь (на всякий случай, дёшево).

## 4. API (все защищены)

- `GET /api/goals` — список целей с таргетами.
- `POST /api/goals`, `PATCH/DELETE /api/goals/[id]` — CRUD.
- `GET /api/goals/dashboard` — материализует и возвращает: `current[]` (идущие окна с прогрессом по таргетам), `overdue[]` (просроченные неподтверждённые), `upcomingToday[]` (окна, которые начнутся сегодня позже).
- `POST /api/goals/instances/[id]/ack` — закрыть просроченный instance (убрать из индикаторов).

## 5. UI

1. **Страница/вкладка «Цели»** (в ViewTabs или отдельный пункт сайдбара): список целей, CRUD-диалог (имя, окно, дни недели, список таргетов «направление/проект + количество», add/remove таргет), у каждой цели — прогресс текущего окна (полоски «1/1», «0/1»).
2. **Вид «Сегодня»:** новая секция «Цели» сверху — идущие окна с прогрессом и оставшимся временем, просроченные — красным.
3. **Все страницы:** индикатор в шапке/сайдбаре — красный бейдж со счётчиком просроченных целей (рядом с переключателем видов или в сайдбаре). Клик → переход на «Сегодня»/«Цели». Подхват: `useGoalsDashboard` hook с периодическим refetch (60 с).
4. Задачи, выполненные в окне, засчитываются автоматически — никаких ручных привязок задачи к цели не делаем (KISS).

## 6. Миграция БД

Новые таблицы: `Goal`, `GoalTarget`, `GoalInstance` (+ `acknowledgedAt` у instance). Индексы: `GoalInstance(goalId, windowEnd)`, `GoalTarget(goalId)`.

## 7. Итерации

**G1. Backend (1 день):** миграция, zod-схемы, `goalService` (CRUD + материализация + прогресс + статусы), API, Vitest: расчёт прогресса (засчитываются только completedAt в окне и нужного scope), материализация (идемпотентна, окно через полночь), переход в overdue, ack.

**G2. UI (1 день):** вкладка/страница «Цели» с CRUD-диалогом и прогрессом; секция в «Сегодня»; бейдж просроченных целей в шапке на всех страницах; e2e smoke (создать цель → видна на дашборде).

## 8. Принятые решения

1. Расписание: **ежедневно или выбранные дни недели** (без произвольных диапазонов дат).
2. Просроченная цель: бейдж + секции сразу, **push-уведомление «цель просрочена» — добавить в объём M4**.
3. Зачёт: факт `completedAt` в окне, **плюс «в рамках дня»** — завершённая позже задача закрывает самое раннее невыполненное окно этого дня; прошлые дни — только ack.
